## D-006 (2026-08-25) Design lessons imported from 2604.00818
1. Training mixes **no-malrule correct-solving dialogues** to enforce misconception
   boundaries (they showed over-application otherwise) → also motivates H5.
2. Student answers include **intermediate step traces**, not bare final answers
   (they showed step traces are essential for acquisition). MalruleLib's executable
   malrules provide these step traces natively.

## D-007 (2026-08-25) Data pipeline principle: code computes math, GLM drafts prose
Student mathematical content (answers + step traces) is **always computed by
MalruleLib executables**, never generated by an LLM. GLM-5.3 (institutional gateway) drafts only
tutor turns and natural-language phrasing around code-computed math. This makes
answer-leak a property to *audit* (tutor-side) rather than *hope for* (student-side),
and makes turn probes exact-match verifiable by construction.

## D-010 (2026-08-25) Render-check design: hard checks vs soft warnings
Pilot smoke exposed two false-positive classes in naive leak detection: (a) the
correct answer literally appears in the problem statement (intercept/equation
questions); (b) the student's *wrong* computation passes through an intermediate
value equal to the correct answer (e.g. 16−12=4). Policy: tutor-side leak checks
are HARD but exempted when the correct answer occurs in the problem text;
student-side correct-answer sightings are SOFT warnings stored per dialogue and
routed to hand audit. Hard guarantees kept: student's final answer == code-computed
malrule answer (whitespace-flexible bounded match), tutor pre-remediation no-leak,
problem statements verbatim, remediation contains the correct answer.

## D-011 (2026-08-25) Simulator conditioning: one model, system-prompt-assigned misconception
One model serves all misconceptions. The system prompt carries the assigned
misconception description (from MalruleLib); correct-solving mix-in dialogues get a
correct-student persona instead. Dialogue turns map tutor→user, student→assistant;
SFT loss on assistant tokens only (exact masking via incremental-prefix
tokenization). Rationale: (a) per-malrule models don't scale to 102 malrules;
(b) matches the deployment story (a tutor-trainer assigns a persona at runtime);
(c) makes H3 selectivity meaningful — the model must *read* the assigned
misconception, not memorize one. Implemented in `harness/train_sft.py`.
To finalize at preregistration freeze (8/26).

## D-012 (2026-08-25) Probe evaluation protocol (headline metric harness)
Implemented in `harness/probe_eval.py`; frozen with the probe sets at the 8/26
preregistration freeze.
- **Dialogue mode** (H1/H2/H3): held-out eval dialogues (scaffold seed 20267777,
  327 dialogues, problem texts disjoint from both probe sets AND the 16k training
  pool by construction). System prompt assigns the misconception (D-011); tutor
  turns are *scripted* from the rendered eval dialogue; student turns are generated
  **on-policy** by the model under evaluation. Probe points: k=0 (pre-dialogue
  anchor) and after each on-policy student turn. A probe fork = history + probe
  problem as a user turn ("Try this one: ..."); forks are discarded and never
  contaminate the main trajectory. Probes drawn deterministically per dialogue
  (rng seeded by dialogue_id) from the frozen probe sets, distinct within a
  dialogue, same malrule as the dialogue.
- **Static mode**: single-turn probes under a persona. misconception-persona on
  hold probes = enactment; correct-persona on correct probes = collateral (H5).
- **Classification** (zero LLM judges): `answer_eq.extract_final_answer` (frozen
  deterministic extractor: last answer cue → algebraic tail or first numeric
  candidate; else last numeric candidate) then `answers_equal` against the
  code-computed malrule/correct answers → {malrule, correct, other}.
- **Decoding**: Qwen3 non-thinking as-served defaults (temperature 0.7, top_p 0.8,
  top_k 20), seeded; `--greedy` available as a documented ablation only.
- **Flip metrics from probe points**: targeted-flip = P(correct | flip_targeted,
  k≥3); misaligned-flip = P(correct | flip_misaligned, k≥3); generic-flip =
  P(correct | hold, k≥4, i.e. post challenge_generic); selectivity per PLAN §3.
- Baselines (prompt-only base models) use the *same* harness and probes.

## D-012a (2026-08-25) Pre-freeze harness validation fixes
End-to-end validation on the smoke model exposed extractor blind spots; fixed
before freeze: (a) probe template now instructs an explicit final line
("Answer: ..."); (b) cue tiers — strong cues ('answer') trusted, weak cues
('which is', '=') overridable by later candidates; (c) algebraic chars extended
to ^ (exponent answers); (d) phrase answers returned whole from strong-cue tails
("no solution", "YES"); (e) comparator strips trailing *prose* parentheticals
symmetrically ("No solution (abs value cannot be negative)" == "no solution"),
keeping math parentheticals ("(x-3)(x+2)") intact. Probe sets NOT filtered:
~5% of probe answers are prose phrases relying on symbolic match; the fraction
of 'other' classifications is reported and spot-checked by hand (aux only).
(f) unicode superscripts normalized (x¹⁵ == x^15); numeric powers evaluated
(3^8 == 6561, bounded); power-form answers compare by exponent with base
matching relaxed for MalruleLib's canonical placeholder base x (v^10 == x^10,
2^12 == x^12) — the library stores power answers with base x even when the
problem uses another base (128 probe entries affected, verified by scan).
Self-tests: 53/53 in harness/answer_eq.py.

## D-016 (2026-08-25) Infra incident: FSDP FULL_STATE_DICT gather race corrupted 8B saves
Two 8B FSDP smoke checkpoints (trainer.save_model fp32 33G, then explicit
bf16 rank-0 gather 16G) were corrupted identically: layer-35 (the LAST
FSDP unit) MLP tensors held misplaced weight-like values at millions of
scattered positions, up_proj maxdiff 28.1414 bit-identical across both
runs; all other tensors at training-physics scale (~6e-5 for 6 AdamW steps
at lr 1e-5). Diagnosis chain: (a) two different serializations decode to
the same corrupt values → the gathered state dict was already corrupt in
memory; the filesystem is exonerated — the initial "full PVC" hypothesis
was wrong (reproduced bit-identically with 402G free); (b) corruption is
confined to the shard contributions of ranks ≥1 of the last-gathered unit
(rank-0's block clean); (c) lr=0 isolation (`harness/fsdp_save_test.py`)
is clean at 0.6B AND 8B on both save paths under a light workload → the
FULL_STATE_DICT offload_to_cpu D2H copy can race ahead of collective/copy
completion, but only under real-workload stream backlog (epochs + evals);
it is deterministic given identical preceding work, hence the bit-identical
corruption across runs.
Mitigations (train_sft.py / run_cell.sh):
- torch.cuda.synchronize() around the gather;
- live-generation canary BEFORE save (separates training-side failures
  from save-side failures);
- post-save integrity gate: every saved tensor compared EXACTLY against a
  `summon_full_params` materialization (an independent path); mismatch →
  final/ renamed to final.CORRUPT + hard failure;
- `harness/gen_check.py` cold-load degeneracy check between train and eval
  in run_cell.sh (exit 1 blocks the cell);
- retained from the first pass: no mid-run checkpoints by default (fp32
  optimizer state ≈96G/ckpt at 8B), FSDP finals saved bf16 (33G→16.4G at
  8B), run_cell.sh refuses to start with <100G free.
Validated on the relaunched 8B smoke: live-gen coherent, [verify] 399/399
exact, cold gen_check PASS, layer-35 maxdiff vs base 6.1e-5 (training
scale). Corrupt artifact kept: runs/fsdp-smoke-8b/final.CORRUPT-incident.
